# Техническое задание: ESP32 Sensor Station

## 1. Общие сведения

### 1.1 Название проекта

**ESP32 Sensor Station** — IoT-станция на ESP32 WROOM-32 для сбора данных с датчиков, отображения информации на OLED-дисплее, публикации телеметрии через MQTT и настройки через веб-интерфейс.

### 1.2 Цель проекта

Разработать прошивку, которая:

- собирает данные с подключённых датчиков;
- отображает статус системы и показания на SSD1306 128×64;
- позволяет настраивать Wi‑Fi, точку доступа, MQTT-брокеры и датчики через веб-интерфейс;
- публикует телеметрию в локальный или облачный MQTT-брокер;
- поддерживает MQTT без TLS и MQTT over TLS;
- сохраняет локальную историю измерений за последние 24 часа;
- сохраняет конфигурацию между перезагрузками;
- работает от USB или аккумулятора;
- остаётся работоспособной при отсутствии Wi‑Fi, MQTT или отдельных датчиков.

### 1.3 Зафиксированная платформа

| Параметр | Значение |
|---|---|
| Контроллер | ESP32 WROOM-32 |
| Дисплей | SSD1306 OLED, I2C |
| Разрешение дисплея | 128×64 |
| Wi‑Fi | 2.4 ГГц, STA и AP |
| MQTT | Локальный или облачный брокер |
| Безопасность MQTT | Без TLS либо MQTT over TLS |
| История измерений | Локально, последние 24 часа |
| Питание | USB 5 V или аккумулятор |
| Среда разработки | ESP-IDF, FreeRTOS |
| Язык интерфейса | Английский |

## 2. Аппаратная конфигурация

### 2.1 Обязательное оборудование

| Компонент | Назначение |
|---|---|
| ESP32 WROOM-32 DevKit | Основной контроллер |
| SSD1306 128×64, I2C | Отображение экранов и меню |
| BUTTON_1…BUTTON_5 | Навигация по экранам и меню |
| TOUCH_BUTTON | Открытие и закрытие меню |
| DS18B20 | Температура, 1-Wire |
| DHT11 | Температура и влажность |
| BME280 | Температура, влажность, давление |
| BMP280 | Температура и давление |
| BMI160 | Акселерометр и гироскоп |
| Аккумуляторный модуль | Питание от батареи, зарядка и защита |
| Делитель напряжения | Измерение напряжения аккумулятора |

### 2.2 Требования к пинам

- Все назначения пинов выносятся в `board_config.h`.
- Запрещено использовать strapping pins, flash/PSRAM и UART0 при наличии USB-консоли.
- SSD1306, BME280, BMP280 и BMI160 работают по общей шине I2C.
- I2C-адреса должны быть уникальными.
- DS18B20 использует 1-Wire; несколько датчиков могут работать на одной шине при уникальных 64-битных адресах.
- При конфликте пинов, I2C-адресов или интерфейсов сохранение конфигурации блокируется с понятной ошибкой.

### 2.3 Базовое распределение I2C

| Устройство | Интерфейс | Возможные адреса |
|---|---|---|
| SSD1306 128×64 | I2C | `0x3C`, `0x3D` |
| BME280 | I2C | `0x76`, `0x77` |
| BMP280 | I2C | `0x76`, `0x77` |
| BMI160 | I2C | `0x68`, `0x69` |

Конкретные пины I2C, кнопок, ADC, 1-Wire и датчиков задаются в `board_config.h`.

## 3. Программная архитектура

### 3.1 Принципы

- Модульность: каждый функциональный блок — отдельный компонент.
- Разделение ответственности: датчики, сеть, UI, хранилище и питание не зависят друг от друга напрямую.
- Событийная модель: задачи обмениваются данными через очереди, event groups и потокобезопасные структуры.
- UI не блокируется сетевыми операциями или чтением датчиков.
- Конфигурируемость: пины, интервалы, Wi‑Fi, MQTT и датчики задаются конфигурацией.
- Отказоустойчивость: ошибка одного компонента не останавливает устройство.

### 3.2 Состав модулей

| Модуль | Ответственность |
|---|---|
| `app_main` | Инициализация системы, запуск задач, обработка критических ошибок |
| `board_config` | Пины, адреса, аппаратные параметры, профиль питания |
| `config_store` | Чтение и запись конфигурации в NVS и LittleFS |
| `sensor_manager` | Регистрация, инициализация, опрос, валидация и кэширование датчиков |
| `display_manager` | Управление SSD1306, экранами, меню и подсветкой |
| `input_manager` | Обработка кнопок, антидребезг, длинные нажатия |
| `wifi_manager` | STA, AP, автоподключение, мониторинг состояния |
| `mqtt_manager` | Подключение к брокерам, переподключение, публикация, TLS |
| `web_server` | REST API, веб-интерфейс, OTA |
| `time_service` | NTP-синхронизация и локальное время |
| `history_store` | Локальное хранение истории за 24 часа |
| `power_manager` | Профиль питания, мониторинг батареи, deep sleep |
| `diagnostics` | Логи, ошибки, версия прошивки, uptime, heap, причина перезагрузки |

### 3.3 Задачи FreeRTOS

| Задача | Приоритет | Периодичность |
|---|---:|---|
| UI task | Высокий | 30–60 мс или по событию |
| Sensor task | Средний | Индивидуальный интервал каждого датчика |
| Network task | Средний | Событийно |
| MQTT task | Средний | Событийно |
| History task | Низкий | По событию измерения |
| Diagnostics task | Низкий | 10–60 секунд |

## 4. Датчики

### 4.1 Поддерживаемые датчики

| Датчик | Интерфейс | Основные данные | Рекомендуемый период |
|---|---|---|---:|
| DS18B20 | 1-Wire | Температура | 5–10 с |
| DHT11 | 1-Wire-подобный | Температура, влажность | 10–15 с |
| BME280 | I2C/SPI | Температура, влажность, давление | 2–5 с |
| BMP280 | I2C/SPI | Температура, давление | 2–5 с |
| BMI160 | I2C/SPI | Акселерометр, гироскоп | 50–200 мс |
| HC-SR04 | GPIO | Расстояние | 0.5–5 с |
| PIR | GPIO | Движение | По событию |

HC-SR04 и PIR добавляются как дополнительные пресеты для DIY-проектов.

### 4.2 Состояния датчика

- `NOT_CONFIGURED` — добавлен, но не настроен;
- `INITIALIZING` — выполняется инициализация;
- `OK` — данные читаются успешно;
- `WARNING` — данные читаются, но есть некритичная проблема;
- `ERROR` — датчик не отвечает или данные невалидны;
- `DISABLED` — отключён пользователем.

### 4.3 Данные датчика

Для каждого датчика хранятся:

- уникальный ID;
- имя;
- тип;
- интерфейс;
- назначенные пины или I2C-адрес;
- описание;
- состояние;
- время последнего успешного чтения;
- последнее значение;
- интервал опроса;
- признак активности;
- счётчик ошибок.

### 4.4 Пресеты датчиков

Пресет определяет:

- допустимый интерфейс;
- обязательные и опциональные пины;
- I2C-адрес по умолчанию;
- единицы измерения;
- допустимый диапазон значений;
- минимальный и максимальный интервал опроса;
- формат данных для MQTT.

## 5. Локальный интерфейс

### 5.1 Общие требования

- Дисплей SSD1306 128×64, монохромный.
- Все тексты — на английском языке.
- Используются не более двух размеров шрифта: обычный и крупный.
- На экране размещается не более 6 строк.
- Обновление экрана не должно вызывать заметное мерцание.
- Частичная перерисовка предпочтительнее полной перерисовки.

### 5.2 Главный экран

Отображаются:

- дата и время;
- состояние Wi‑Fi;
- состояние MQTT;
- количество активных датчиков;
- IP-адрес или режим AP;
- уровень батареи, если используется аккумулятор;
- uptime.

Пример:

```text
ESP32 Sensor Station     12:04
Wi‑Fi: OK   MQTT: OK
Sensors: 5/5
IP: 192.168.1.42
Battery: 3.9V
Uptime: 02:14:31
```

### 5.3 Экраны датчиков

Для каждого активного датчика создаётся отдельный экран.

Отображаются:

- имя датчика;
- тип;
- текущее значение;
- единицы измерения;
- состояние;
- время последнего успешного обновления;
- сообщение об ошибке при её наличии.

Пример:

```text
BME280: Room climate
T: 23.4 C
H: 48.2 %
P: 1013.1 hPa
Status: OK
Updated: 12:04:11
```

Для BMI160:

```text
BMI160
AX: 0.12  AY: -0.04  AZ: 9.78
GX: 0.01  GY: -0.02  GZ: 0.00
Status: OK
```

### 5.4 Экран Wi‑Fi

Отображается при наличии Wi‑Fi:

- режим: STA или AP;
- SSID;
- IP-адрес;
- gateway;
- MAC;
- RSSI;
- количество клиентов в AP-режиме.

### 5.5 Системный экран

Отображаются:

- модель чипа;
- версия прошивки;
- версия ESP-IDF;
- uptime;
- свободный heap;
- минимальный свободный heap;
- температура чипа, если доступна;
- причина последней перезагрузки;
- источник питания.

## 6. Навигация

### 6.1 Навигация по экранам

| Действие | Кнопка |
|---|---|
| Следующий экран | `BUTTON_3` |
| Предыдущий экран | `BUTTON_1` |
| Первый экран | `BUTTON_2` |
| Последний экран | `BUTTON_4` |
| Выключить или включить дисплей | `BUTTON_5` |
| Открыть меню | `TOUCH_BUTTON` |

Правила:

- с последнего экрана `BUTTON_3` переводит на первый;
- с первого экрана `BUTTON_1` переводит на последний;
- `BUTTON_5` выключает дисплей, повторное нажатие включает его;
- при выключенном дисплее другие кнопки не активируют случайные действия;
- при критическом событии дисплей может включиться автоматически.

### 6.2 Меню

Меню открывается по `TOUCH_BUTTON`.

| Действие | Кнопка |
|---|---|
| Выбор пункта | `BUTTON_5` |
| Вниз | `BUTTON_4` |
| Вверх | `BUTTON_2` |
| Следующий экран / подтверждение | `BUTTON_3` |
| Предыдущий экран / назад | `BUTTON_1` |
| Выход в главный экран | Повторное нажатие `TOUCH_BUTTON` |

### 6.3 Пункты меню

- `Connect Wi‑Fi`;
- `Disconnect Wi‑Fi`;
- `Wi‑Fi Status`;
- `Connect MQTT`;
- `Disconnect MQTT`;
- `Open Web UI`;
- `Restart`;
- `Factory Reset`;
- `Exit`.

Пункт `Open Web UI` показывает локальный IP-адрес устройства.

## 7. Wi‑Fi

### 7.1 Режимы

- `STA` — подключение к роутеру.
- `AP` — собственная точка доступа.
- `AP_STA` — только для первоначальной настройки, если необходимо.

### 7.2 STA-режим

- список сохранённых сетей;
- добавление SSID и пароля;
- подключение к выбранной сети;
- отключение;
- отображение RSSI, IP, gateway и MAC;
- автоматическое переподключение с задержкой;
- хранение нескольких сетей с приоритетом.

### 7.3 AP-режим

- задание SSID и пароля;
- выбор канала;
- отображение IP, MAC и подключённых клиентов;
- ограничение количества клиентов;
- пароль не менее 8 символов для WPA2.

## 8. MQTT

### 8.1 Общие требования

- Поддерживается несколько брокеров.
- Подключение возможно только при активном Wi‑Fi STA.
- При обрыве связи выполняется автоматическое переподключение.
- Датчики продолжают собирать данные при недоступности MQTT.
- Учётные данные и сертификаты не выводятся в логи и веб-интерфейс.
- Каждый брокер имеет уникальное имя и статус подключения.

### 8.2 Конфигурация брокера

```json
{
  "id": "broker_1",
  "name": "Local broker",
  "host": "192.168.1.10",
  "port": 1883,
  "username": "device",
  "password": "********",
  "client_id": "esp32-station-a1b2c3",
  "tls_enabled": false,
  "ca_certificate": "",
  "client_certificate": "",
  "client_key": "",
  "insecure_skip_verify": false,
  "keepalive_s": 30,
  "enabled": true
}
```

### 8.3 Правила TLS

- `tls_enabled: false` — обычный MQTT, обычно порт `1883`.
- `tls_enabled: true` — MQTT over TLS, обычно порт `8883`.
- По умолчанию включена проверка сертификата брокера.
- Для TLS требуется CA-сертификат брокера.
- При взаимной аутентификации используются клиентский сертификат и приватный ключ.
- `insecure_skip_verify: true` разрешён только для локальной отладки и сопровождается предупреждением в веб-интерфейсе.

### 8.4 Формат топиков

```text
<base_topic>/<device_id>/sensor/<sensor_id>/state
<base_topic>/<device_id>/sensor/<sensor_id>/status
<base_topic>/<device_id>/system/state
<base_topic>/<device_id>/system/command
```

Пример:

```text
esp32-station/a1b2c3/sensor/bme280_1/state
```

### 8.5 Формат сообщения датчика

```json
{
  "sensor_id": "bme280_1",
  "type": "BME280",
  "timestamp": 1762068000,
  "values": {
    "temperature_c": 23.4,
    "humidity_pct": 48.2,
    "pressure_hpa": 1013.1
  },
  "status": "OK"
}
```

### 8.6 Единицы измерения

| Величина | Единица |
|---|---|
| Температура | °C |
| Влажность | % |
| Давление | гПа |
| Ускорение | м/с² |
| Угловая скорость | рад/с |
| Расстояние | см или м |
| Напряжение батареи | В |

## 9. Локальная история измерений

### 9.1 Требования

- История хранится локально на ESP32.
- Глубина истории — последние 24 часа.
- Для каждого включённого датчика хранится отдельный временной ряд.
- История используется для графиков в веб-интерфейсе.
- История сохраняется после перезагрузки устройства.
- При переполнении хранилища самые старые записи удаляются первыми.
- История не публикуется в MQTT целиком; в MQTT отправляются текущие измерения.

### 9.2 Хранение

- Основной формат — Ring Buffer в RAM с периодическим сохранением в LittleFS.
- При глубине 24 часа интервал записи истории должен быть настраиваемым.
- Рекомендуемый интервал записи истории: от 10 секунд до 10 минут.
- Для датчиков с высокой частотой опроса, например BMI160, в историю записывается усреднённое значение, а не каждая выборка.
- Максимальный объём истории ограничивается доступным местом на LittleFS.

### 9.3 Формат записи

```json
{
  "sensor_id": "bme280_1",
  "timestamp": 1762068000,
  "values": {
    "temperature_c": 23.4,
    "humidity_pct": 48.2,
    "pressure_hpa": 1013.1
  },
  "status": "OK"
}
```

### 9.4 API истории

```text
GET /api/v1/sensors/{sensor_id}/history?range=24h
GET /api/v1/sensors/{sensor_id}/history?from=<unix_time>&to=<unix_time>
DELETE /api/v1/history
```

Ответ должен содержать массив точек `{ timestamp, values, status }`.

## 10. Веб-интерфейс

### 10.1 Общие требования

- Работает в браузере без установки дополнительного ПО.
- Адаптивная вёрстка для телефона и компьютера.
- Современный UI: карточки, таблицы, индикаторы состояния, графики.
- Все операции сопровождаются сообщениями об успехе или ошибке.
- Веб-интерфейс работает при отсутствии MQTT.
- Доступ защищён паролем администратора.

### 10.2 Вкладка Dashboard

Для каждого активного датчика отображаются:

- текущее значение;
- статус;
- время последнего обновления;
- график за последние 24 часа из локальной истории;
- кнопка ручного обновления.

### 10.3 Вкладка Sensors

Таблица:

| Name | Type | Interface | Pins / Address | Description | Status | Actions |
|---|---|---|---|---|---|---|

Действия:

- `Add sensor`;
- `Edit`;
- `Delete`;
- `Enable / Disable`;
- `Test connection`.

При добавлении датчика пользователь выбирает:

1. тип из пресета;
2. имя;
3. интерфейс;
4. пины или I2C-адрес;
5. интервал опроса;
6. интервал записи в историю;
7. описание.

Система проверяет:

- существование и доступность пина;
- занятость пина другим устройством;
- допустимость интерфейса для выбранного типа;
- конфликт I2C-адресов;
- корректность интервалов опроса и записи истории.

### 10.4 Вкладка Network

Переключатель режимов:

- `Station mode`;
- `Access Point mode`.

В Station mode:

- текущее подключение: SSID, IP, gateway, MAC, RSSI;
- список сохранённых сетей;
- добавление новой сети;
- подключение и отключение.

В Access Point mode:

- SSID;
- пароль;
- канал;
- IP и MAC;
- список подключённых клиентов.

### 10.5 Вкладка MQTT

Отображается только в Station mode.

Таблица брокеров:

| Name | Host | Port | Username | TLS | Status | Actions |
|---|---|---|---|---|---|---|

Возможности:

- добавить брокер;
- изменить брокер;
- удалить брокер;
- проверить подключение;
- включить или отключить брокер.

### 10.6 Вкладка MQTT Routing

Позволяет связать датчик, брокер и topic.

Таблица:

| Sensor | Broker | Topic | Retain | QoS | Status | Actions |
|---|---|---|---|---|---|---|

При добавлении привязки выбираются:

- датчик;
- брокер;
- базовый topic;
- QoS: 0, 1 или 2;
- флаг retain.

## 11. Хранение конфигурации

### 11.1 Разделение хранилищ

| Данные | Хранилище |
|---|---|
| Пароли Wi‑Fi | NVS |
| Учётные данные MQTT | NVS |
| Список датчиков | LittleFS, JSON |
| История за 24 часа | Ring Buffer + LittleFS |
| Системные настройки | NVS |
| Сертификаты TLS | LittleFS или NVS |

### 11.2 Пример конфигурации датчика

```json
{
  "id": "bme280_1",
  "name": "Room climate",
  "type": "BME280",
  "interface": "I2C",
  "address": "0x76",
  "pins": {
    "sda": 21,
    "scl": 22
  },
  "poll_interval_ms": 3000,
  "history_interval_ms": 60000,
  "enabled": true,
  "description": "Indoor temperature, humidity and pressure"
}
```

### 11.3 Правила хранения

- Конфигурация сохраняется только после успешной валидации.
- При повреждении JSON используется резервная конфигурация.
- Пароли не отображаются после сохранения.
- Factory reset удаляет Wi‑Fi, MQTT, пользовательские датчики и историю.

## 12. Питание

### 12.1 Профили питания

```c
typedef enum {
    POWER_SOURCE_USB,
    POWER_SOURCE_BATTERY
} power_source_t;
```

| Функция | USB-профиль | Аккумуляторный профиль |
|---|---|---|
| Дисплей | Включён | Автоотключение через 15–60 с |
| Wi‑Fi | Постоянно | Периодическое подключение |
| MQTT | Постоянное соединение | Пакетная отправка |
| Веб-интерфейс | Доступен постоянно | Доступен во время активного Wi‑Fi |
| Опрос датчиков | По configured interval | Увеличенный интервал |
| История | Непрерывная запись | Запись при каждом цикле измерения |
| Deep sleep | Не используется по умолчанию | Используется между циклами |

### 12.2 Конфигурация питания

```json
{
  "power": {
    "source": "BATTERY",
    "battery_adc_pin": 34,
    "battery_voltage_divider_ratio": 2.0,
    "low_battery_threshold_v": 3.3,
    "critical_battery_threshold_v": 3.1,
    "display_timeout_s": 30,
    "measurement_interval_s": 60,
    "history_interval_s": 300,
    "enable_deep_sleep": true,
    "deep_sleep_s": 300
  }
}
```

### 12.3 Аккумуляторный режим

Цикл работы:

1. Пробуждение по таймеру.
2. Инициализация необходимых датчиков.
3. Чтение показаний.
4. Сохранение измерений в историю.
5. Подключение Wi‑Fi.
6. Отправка текущих и накопленных данных в MQTT.
7. Переход в deep sleep.

Дополнительные требования:

- измерение напряжения аккумулятора через ADC и делитель напряжения;
- отображение уровня заряда на главном экране;
- предупреждение при низком заряде;
- при критически низком заряде отключение Wi‑Fi, MQTT и веб-интерфейса;
- сохранение конфигурации и истории перед переходом в deep sleep;
- пробуждение по таймеру и, при необходимости, по кнопке.

## 13. Надёжность и безопасность

### 13.1 Надёжность

- Watchdog для основной задачи.
- Автоматический перезапуск зависших задач.
- Очереди событий вместо глобальных блокировок.
- Проверка целостности JSON-конфигурации при загрузке.
- Fallback-конфигурация при повреждении файла.
- Ограничение размера журнала.
- Обработка ошибок датчиков без остановки остальных.
- Автоматическое восстановление Wi‑Fi и MQTT.
- Сохранение истории при перезагрузке и переходе в deep sleep.

### 13.2 Безопасность

- Пароли не отображаются в веб-интерфейсе после сохранения.
- Пароли, ключи и сертификаты не выводятся в логи.
- Веб-интерфейс защищён паролем администратора.
- MQTT over TLS включается для каждого брокера отдельно.
- OTA-обновление доступно только после аутентификации.
- Factory reset требует подтверждения.

## 14. Загрузка и обновление

### 14.1 Splash screen

При старте отображается графическая заставка:

- логотип проекта;
- индикатор инициализации;
- короткие статусы: `Storage`, `Display`, `Sensors`, `Network`.

Заставка не блокирует загрузку дольше 2–3 секунд.

### 14.2 OTA

- OTA-обновление через веб-интерфейс.
- Проверка версии и целостности образа.
- Автоматический откат при неудачном обновлении.
- Отображение прогресса на дисплее и в веб-интерфейсе.
- Сохранение конфигурации и истории после обновления.

## 15. Нефункциональные требования

- Время загрузки до рабочего экрана — не более 5 секунд.
- Отклик UI на нажатие кнопки — не более 100 мс.
- Веб-страница открывается не более чем за 2 секунды в локальной сети.
- Потеря Wi‑Fi или MQTT не останавливает сбор данных, работу дисплея и запись истории.
- Ошибка одного датчика не влияет на остальные датчики.
- Код модульный, с понятными именами файлов, функций и структур.
- Публичные функции и сложные участки кода сопровождаются комментариями.
- В репозитории должны быть `README.md`, инструкция по сборке, инструкция по первичной настройке, описание REST API и схема подключения.

## 16. Критерии приёмки

Система считается готовой, если:

1. После включения отображается заставка, затем главный экран.
2. SSD1306 128×64 корректно инициализируется по I2C и отображает все экраны.
3. Датчики опрашиваются по своим интервалам и отображаются на отдельных экранах.
4. Отключение одного датчика не нарушает работу остальных.
5. Кнопки корректно листают экраны, открывают меню и управляют подсветкой.
6. Wi‑Fi STA и AP настраиваются через веб-интерфейс и сохраняются после перезагрузки.
7. Устройство работает с локальным MQTT без TLS.
8. Устройство работает с облачным MQTT over TLS.
9. Неверный сертификат брокера блокирует TLS-подключение с понятной ошибкой.
10. Датчик можно добавить, изменить, отключить и удалить через веб-интерфейс.
11. Конфликт пинов или I2C-адресов блокируется с понятной ошибкой.
12. Веб-интерфейс показывает текущие значения и графики за последние 24 часа.
13. История измерений сохраняется после перезагрузки.
14. После перезагрузки все настройки, датчики и привязки MQTT сохраняются.
15. В USB-режиме Wi‑Fi, MQTT, веб-интерфейс и запись истории работают непрерывно.
16. В аккумуляторном режиме устройство выполняет цикл «измерение → сохранение истории → отправка → deep sleep».
17. При низком заряде батареи отображается предупреждение и снижается энергопотребление.
18. OTA-обновление проходит успешно и не приводит к потере конфигурации и истории.
